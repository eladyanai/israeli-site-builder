# The process in detail

Classify first: new site, redesign, polish, or a page inside an existing site. That decides what may change.

## 1. Discovery and planning
Ask, do not guess: what the business sells, to whom, the wanted action per page, what exists already.
Output: brief, sitemap, customer journey, message bank. Gate: brief approved.
Common failure: jumping to design because the request sounded clear.

## 2. Content
Collect materials, differentiation, calls to action, copy. Every testimonial, number and certificate needs a source. Missing items go on a list for the client (`client-materials.md`).
Gate: messages approved. Common failure: filling a gap with a testimonial that sounds real.

## 3. Visual design
New brand: brand language, then 2-3 styles including image style, then a locked kit (`design-kit.md`), then page directions.
Existing site: find the locked language first. Directions are variations inside it. A new direction changes composition, not colors.
Gate: kit locked and direction chosen, separately.

## 4. Build
Inventory what the site already has, then build from it, on staging when possible. For Elementor read `elementor.md`.
Gate: approval before any write to a live site. Common failure: raw HTML the client cannot edit.

## 5. QA
Run `ready-checks.md` in a real browser and write a report that includes what was not checked.
Gate: "ready" only after the report. Common failure: a good screenshot of a page whose menu does not open.

## 6. Marketing and SEO
Run `launch-checklist.md`. Gate: approval to go live. Common failure: a live site still blocked from search engines.

## 7. Maintenance
Backups, updates, periodic review and a handover document. Suggested rhythm: at least every six months, quarterly for shops.

## Redesign or polish
Inventory every component first, including galleries, animations and icons. Nothing is removed without approval by name. Motion that worked stays and takes the new colors. Before and after screenshots go to approval before upload.
